# Request reader 移动设计

对象：在手机上核对 CPA 多轮请求的人。页面唯一工作是读清本轮用户提问、模型回答，并能追溯系统和历史消息。

## 设计计划与取舍

采用会话阅读器：紧凑会话封面 → 请求时间与模型 → 用户卡片 → 回答卡片 → 按需上下文。放弃大号统计面板和每层容器重复留白；信息层级由角色表达。

颜色：纸面使用现有 `--bg-primary`，底层使用 `--bg-secondary`（随深浅主题）；用户蓝 #4278bf、回答绿 #31836e、系统紫 #8964bd；正文/边界沿用主题。角色低饱和底色通过 color-mix 派生，保持深色模式可读。

字号：页标题 20px/650；会话模型 14px/650；对话正文系统中文无衬线 14px/1.75；时间和数据 10–12px/tabular-nums；UUID 使用 ui-monospace 10px，仅展开后显示。阅读优先，不下载外部字体。

布局：手机外边距 10px，卡片内边距 12px，请求间隔 12px。所有主要可点击项最小44px；正文自然换行；长上下文12K分页。会话折叠后只保留模型、时间、请求数，UUID进入次级层。筛选默认折叠，视图切换始终直接可见。

标志性元素：蓝/绿/紫角色阅读卡片让“谁说的”无需阅读正文就能辨认，文字标题同时保留以免仅靠颜色区分。系统/开发者各自保留原角色，历史按原顺序；原始 JSON 是二级入口。

## 自审

不增加装饰性hero、渐变或动效。不使用窄屏左右气泡压缩长Prompt；采用满宽阅读卡。Session长UUID不再抢占首屏。角色上下文只在展开时请求，避免UI优化抵消既有性能优化。构建与组件验证不替代运行截图验收。
