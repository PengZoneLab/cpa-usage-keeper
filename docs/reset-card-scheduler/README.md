# Codex 重置卡定时任务

在 Codex 账户编辑弹窗的“重置卡”区域独立保存。默认无预约、临期策略关闭。已停用的账户也能配置并执行。

- 单卡预约：选择精确卡 ID，设置至少 3 分钟后的最晚使用时间 T，可修改或取消未尝试任务。
- 账户临期策略：T 为每张卡到期前 10 分钟；同卡两种规则取较早时间，只消费一次。
- 每分钟检查。T 前 3 分钟停止新请求；最后一分钟检查时取消该账户剩余生成请求，确认 CPA 本地执行为零后再发起消费。超过 T 不发起消费，记录 deadline_missed。
- 消费后保持停用。显式手动启用且没有待执行任务时，可解除重置任务产生的停用；人工截止时间和额度下限仍有效。
- 任务派生截止时间独立于人工截止时间。取消或后移任务会重算尚未生效的派生截止；已停用的账户不因取消自动恢复。
- 消费超时或进程在发出消费后中断，记为 uncertain，不盲目重试。已知尚未发出消费请求的失败可以在截止前重试，沿用持久化幂等 ID。
- 上游返回 nothing_to_reset 表示无可重置额度，不宣称已成功；不连续消耗其他卡。

## CPA 依赖

必须先安装 [固定 v8.0.40 的账户取消补丁](../../deploy/cpa-reset-guard/README.md)。旧版或排空失败均阻止消费。仅生成路径纳入取消；管理 APICall 查询和消费仍可对停用账户执行。不调用 cooldown/reset。

取消可以确认 CPA 本地上游执行已结束，不能承诺上游服务即时停止计算或没有延迟结算。

## 管理接口

- GET `/api/v1/credentials/:auth_index/reset-schedule`
- PUT 同路径：`{"auto_before_expiry":true}` / `false`
- PUT `/api/v1/credentials/:auth_index/reset-schedule/cards/:credit_id`：`{"scheduled_at":"2026-10-30T02:00:00+08:00"}`；`null` 取消。

接口均沿用管理员认证、请求意图与 CSRF 保护。配置、卡任务及幂等 ID 存储在 Keeper 数据库的新表，不修改原始登录文件内容。

## 限定真实验收范围

可设置 `RESET_SCHEDULE_ALLOWED_CREDITS` 为 `{"auth_index":["credit_id"]}` JSON 白名单。只限制定时消费；不在白名单的账户/卡绝不发送消费请求。空字符串或未设置表示无额外限制，显式 `{}` 禁止所有定时消费。格式错误阻止服务启动。真实验收使用私有白名单与账本，账户标识不提交公共仓库；验收后关闭测试策略。
