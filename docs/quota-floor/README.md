# 单账号最低剩余额度

在 Auth Files 的账号编辑弹窗中填写“最低剩余额度（%）”，并保存。

- 范围为 0–100，可填小数。留空关闭限制；0 表示额度耗尽时暂停，100 表示立即暂停。
- 默认不启用。配置只属于当前 Auth File，不属于调用方 API Key。
- Keeper 每分钟查询已配置账号的上游额度。任一可用窗口的剩余百分比小于或等于下限时，通过现有 CPA 管理接口暂停账号。
- 只有所有已观察到的窗口都有完整数据且高于下限，才恢复由本规则暂停的账号。窗口消失、数据缺失或查询失败时不恢复。
- 修改下限后立即排队检查。清空下限会解除规则自己的暂停，不解除人工停用。
- Keeper 的单条与批量停用都会保存人工停用标记。规则暂停后，可在编辑弹窗选择“保持人工停用”。手动启用前会检查最新额度。
- 配置、停用归属和人工停用标记都持久化，进程重启后继续生效。

## 边界

这是基于定时额度快照的账号保护，不是供应商账单的同步硬上限。检查周期、网络延迟和在途请求可能使实际剩余额度低于设定下限。Keeper 停机期间没有新的保护动作；已在 CPA 暂停的账号保持暂停。

只使用上游真实额度，不根据调用次数或 tokens 猜测百分比。关闭的额外付费额度不参与判断。一个可用额度窗口达到下限会暂停整个账号，包括代码审查或模型专属窗口。

人工停用应通过 Keeper 操作。若绕过 Keeper，在 CPA 中对一个已经由规则暂停的账号再次提交相同的停用状态，CPA 的布尔状态不能表达这次人工意图，Keeper 无法可靠识别。对原本已停用的账号配置规则时，会保留人工停用。

## 实现

复用 `quota.Service.Check`、现有 CPA `UpdateCredentialStatus` 接口、凭据文件锁和 metadata 协调器。未修改 CPA 二进制或插件。

`credential_quota_floors` 是 Keeper 私有表，由增量迁移创建。CPA 元数据同步不覆盖它。人工操作与自动操作共用文件锁。先保存停用意图，再调用 CPA；远端更新失败可重试。

管理员接口：

- `GET /api/v1/credentials/:auth_index/quota-floor`
- `PUT /api/v1/credentials/:auth_index/quota-floor`，请求为 `{"minimum_percent":10}` 或 `{"minimum_percent":null}`。

状态包括未设置、等待检查、监测中、规则暂停、人工停用、额度不可用、更新失败。界面沿用现有 Modal、Input、Button、主题和翻译体系。

## 验证

- Go：阈值边界、账号隔离、重启恢复、查询失败、缺失窗口、人工停用、操作失败重试、接口权限与参数校验。
- React：配置加载、保存、范围校验、清空、失败时保留草稿及原有编辑流程。
- 隔离 CPA：真实模型请求、暂停后拒绝、降低阈值后恢复、重启保留、人工停用优先。
- 浏览器视觉检查受当前 Computer Use URL 限制阻断，未完成；不把交互测试当作视觉验收。

发布前应备份数据库、环境配置与原容器定义。回滚必须同时恢复旧镜像和迁移前的数据库。默认不替任何账号设置具体下限。

2026-10-28：1575 项前端测试通过；Go 全包测试通过（发布脚本测试使用 Python 3.13）；新增服务、API 和额度投影通过 race 检查。前端 lint 无错误，仅保留原 `UsagePage.tsx` 的两条 Hook 依赖警告。
