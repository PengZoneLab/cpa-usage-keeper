# 问题与限制

- I1：周额度历史未直接按模型和 effort 分组。仅接受完整、纯净请求区间；不足时显示无预测，允许显式手填场景需求。
- I2：短窗与周窗百分比基准不同。要求显式短窗满额换算参数，不偷用相同百分比。
- I3：卡后账户保持停用。默认不推演用卡后恢复；用户启用情景后才按明确的人工恢复延时推演，不执行任何变更。
- I4：自然重置后的周期和用卡后恢复100%是预测假设，非查询到的未来事实。结果必须披露。
- I5：离散时间模型、需求低中高场景和求解时限限制必须可见。求解超时不得返回最优标签。

## 已解决问题

- UI R1：全局label/input样式污染、日期末毫秒边界、历史异步旧值、缺少重读/数学公式。已修复，独立R3通过。
- UI R2：验收脚本语言与控件定位、过快完成造成取消定位失败；不是新的产品阻塞。修正fixture并延迟WASM验证取消，独立R3通过。
- 全量测试首次Node26实验WebStorage与happy-dom冲突。沿用既有项目验收方式NODE_OPTIONS=--no-experimental-webstorage复跑，1650通过，未修改产品来迎合环境。
- 新页面Lint错误已修复；仅保留基线UsagePage既有2条Hook warning。

范围内未解决阻断：无。I1–I5是页面已披露的模型/数据限制，不伪装为真实未来事实。
