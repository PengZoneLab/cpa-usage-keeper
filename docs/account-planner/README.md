# 账号优先消耗求解

入口 `/planner`，沿用 Keeper 登录与管理权限。在页面选账号、填写同一模型和 effort、载入历史需求或手填场景需求，再点击计算。全部查询只读。Worker 在浏览器本地运行 HiGHS 1.15.4；不调用LLM、不切换账号、不创建任务、不消费卡。

## 计量

5x 权重1，20x权重2。1个5x满周=100加权周百分点；1个20x满周=200。剩余量 `w × remainingPercent`，不将名称5与20当作倍率，也不换算token。

## 数学模型

每个账号 i、事件区间 k 的消耗为 x(i,k)，单位加权周百分点。所有账号共用一个真实需求上限 d(k)：

`Σ_i x(i,k) ≤ d(k)`，`x(i,k) ≥ 0`。

周与短窗分别维护库存。普通区间 `q_end = q_previous − x`。自然重置边界恢复相应窗容量。最低额度从可用容量扣除。手工截止和现有重置任务的停派截止之后，消耗固定为0；不会因求解而解除原保护。

每张卡在候选时刻的使用变量 y 为0/1，`Σ_k y(card,k) ≤ 1`。恢复库存的双线性项用有界线性约束表达：令C为容量，p为前一库存，z为该时刻是否用卡，丢弃量D满足

`0 ≤ D ≤ C z`，`D ≤ p`，`D ≥ p − C(1−z)`，

于是 `q_end + x = p + Cz − D`。z=0时正常消耗；z=1时恢复至C。自然重置边界直接恢复，不重复增发。

卡候选时刻来自所选时间网格和到期前10分钟；卡前3分钟及人工恢复延时内，账号不得消耗。只在页面明确开启卡后人工恢复场景时才允许y。现有计划的停派仍强制生效。

对每个候选账号i，限制首个事件区间（最多5分钟）只有i能消耗，求

`Q_i = max Σ_k Σ_j x(j,k)`。

选择Q_i最大者。并列依次比较卡到期、自然重置、固定优先级（数值较大优先）和稳定账号键。本月量另行统计，不透支月末决策而忽略跨月收益。

## 精确性与边界

HiGHS返回Optimal且通过所有候选求解，才标“模型内最优”。最多12账号，每账号4卡，规划期62天、1800事件点、160次求解、总预算75秒、单次5秒。超时/失败返回未完成，无候选最优结论。用户可取消Worker。

这是有限事件网格模型的最优，不是连续时间或现实未来的无条件最优。自然重置未来按原周期重复、需求均匀到达、卡恢复周/短窗100%均为公开的场景假设。短窗与周窗的百分比不能直接相加或取最小值；需提供短窗满额对应的加权周百分点。未知权重和过期快照拒绝计算。

低/中/高需求三点分别求解；首选都相同才说场景一致，不称覆盖整个连续预测区间。卡集合经保守筛选：某卡在任一场景中没有严格正的边际增益则排除并重新优化。最终最优以筛选后的卡集合为约束。这比无约束最大值更保守，页面明确说明。

历史只用近7天同模型、同effort、完整请求集合的纯净周额度下降区间；混合未知样本不按token分摊，分页截断/采样预算不足不伪造预测。已观测消耗可能被限额压低，预测不等于未受限制的真实需求。手填数据为情景输入。
